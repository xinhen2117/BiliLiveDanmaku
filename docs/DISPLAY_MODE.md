# 常亮、低功耗与横屏展示

## 使用

- 弹幕页默认保持常亮，只对当前前台窗口生效。可在「显示设置」关闭。返回首页、切后台或屏幕锁定会释放本页的覆盖，不唤醒锁屏，不申请 WakeLock 或修改系统设置。
- 弹幕页亮度图标进入/退出「低功耗展示」。也可在首页设置中设为默认；低功耗模式不会强行开启已关闭的常亮开关。
- 低功耗展示使用纯黑背景、较暗的文字、窗口级亮度（默认 20%，可调 5%–100%），取消持续自动滚动动画。亮度仅属于当前前台弹幕窗口，退出、后台与设置弹窗时恢复原值。
- 控制条在约 8 秒无触摸后隐藏（遵循辅助功能推荐超时）。轻触任何位置恢复控制，仍可滚动；系统边缘手势可临时显示系统栏。返回键第一次退出低功耗，第二次离开房间，不锁住退出路径。
- 「低频移动」默认开启，在低功耗前台每 60 秒将全部应用内容移动到另一位置，包括弹幕、状态、空列表、错误与控制。预留 12dp 安全边距，最大移动 8dp，不只移动消息而留下固定亮按钮。
- 「空闲后渐暗」默认关闭。开启后，收到可显示的新弹幕或触摸会重置等待；等待 30/60/120 秒后先降低文字/窗口亮度，15 秒后进一步降低。它不会调用熄屏、断开或清屏，新弹幕与触摸恢复原显示。普通模式不进行空闲渐暗。

## 横竖屏与可读性

- 不锁方向，按可用窗口宽高调整工具栏间距，兼容横屏与分屏。低功耗隐藏控制后为弹幕释放更多高度。
- 始终按时间顺序单列显示。宽窗口（至少 600dp）使用有界发送人列与弹幕正文列；窄窗口将发送人/时间置于正文上方。长用户名省略显示，但不会挤占正文至不可读；长弹幕完整换行，不再固定截成两行。
- 可调 14–24sp 字号、紧凑行距，字号继续跟随系统字体缩放，不用过小文字强塞消息。
- 使用安全区域 Insets 避免刘海、系统栏/窗口控件遮挡；整块位移使用布局偏移，点击区域随内容一起移动。
- 保留 Navigation 的弹幕 ViewModel 与可保存的 LazyListState/模式；横竖切换不主动重连。手动拖动暂停跟随，点「回到最新」恢复；历史满上限时仍继续跟随新消息。进程被系统终止后的内存历史不承诺恢复。

## 更新与缓存边界

展示管线按需唤醒并合批，普通前台更新间隔至少 50ms，低功耗至少 250ms。无消息时不做 33ms 空轮询，不运行无限逐帧动画。低频位移与可选空闲截止计时只在本页前台运行。

接收总数包含被过滤消息，但仅过滤流量时延后到下一次实际界面事件更新；每秒速率统计可显示的接收消息。后台只保留有界的待处理队列，不持续刷新 UI，也不为了旋转/前后台切换重建连接。历史与队列有数量和文本总量上限。队列最多 512 条、256 Ki 个 UTF-16 代码单元，历史最多按用户设置保留（硬上限 5000 条）、2 Mi 个代码单元。约 0.5 MiB / 4 MiB 仅是文本负载估计，不含对象开销。队列溢出或文本预算淘汰会报告计数，正常历史条数滚动淘汰不计入溢出；这不是完整日志归档或后台保活服务。渐暗本身不额外丢弃消息，已有过滤/重复折叠/数量上限仍适用。

## 不能保证的部分

常亮仍然耗电，纯黑主要降低 OLED 发光功耗，不保证 LCD 有同等收益。低亮度和低频位移只能降低长期静态显示的风险，不能保证不烧屏。系统/厂商仍决定实际亮度、刷新率、后台网络、锁屏与进程存活。应用不强改硬件刷新率，不提供“零功耗”或“完全防烧屏”保证。

桌面窗口标题栏、用户主动调出的系统栏、输入法等由系统控制，不承诺能隐藏或移动。设置弹窗是临时交互界面，不用于长时间展示。

## 验证与尚未验证

纯 JVM 自动测试覆盖设置边界、偏移边界、窗口状态所有权及幂等恢复、恢复后重新获取原亮度、有界批次/过滤/折叠/溢出与更新调度。它们不能证明真实设备功耗、OLED 老化效果或 Android 窗口生命周期行为。

Android 构建仍需完整 SDK/Google Maven 依赖。新增仪器测试用于实际窗口属性恢复，但未运行的测试不得称为通过。应在真实 OLED/LCD 与模拟器上按以下清单验证：

1. 普通/低功耗保持常亮跨越系统自动锁屏时间；常亮关闭后恢复系统超时；电源键始终可锁屏。
2. 进入/退出模式、打开/关闭显示设置、主页/任务切换、锁屏、旋转、重复返回后，亮度/KEEP_SCREEN_ON/系统栏恢复正确。
3. 30 秒渐暗前后接收新弹幕、触摸、滚动，消息恢复且不由渐暗清空；无消息时不常驻高频唤醒。
4. 10/100/300 条每秒：保持缓冲上界、无重复 Lazy 列表 key、历史满额仍跟随、手动拖动/回底部正常；记录溢出数，不隐瞒丢弃。
5. 竖屏/横屏/分屏、刘海与手势/三键导航，系统字体 100%/200%、长中文/英文/emoji/用户名，内容不重叠、正文可滚动阅读，旋转不重复订阅。
6. 等候至少两个位移周期：所有应用亮元素与点击区域一起移动，边缘不裁切；TalkBack 与大字号可恢复控制及退出。
7. 以相同设备、环境亮度、消息速率和网络比较普通/低功耗的电池电流、CPU/帧时间（例如 Perfetto/Android Studio Profiler）；持续温度与亮度控制变量，不用 JVM 耗时替代耗电数据。

## Android 官方依据

- [保持屏幕亮起](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on)：Activity 的 FLAG_KEEP_SCREEN_ON 与退出恢复。
- [WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#screenBrightness)：只覆盖窗口亮度，负值表示使用用户首选亮度。
- [沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)：隐藏系统栏并允许边缘手势临时恢复。
- [Compose 性能实践](https://developer.android.com/develop/ui/compose/performance/bestpractices)：稳定列表 key 与避免不必要计算。
- [适配显示尺寸](https://developer.android.com/develop/ui/compose/layouts/adaptive/support-different-display-sizes)：按可用窗口空间自适应。
- [保存 Compose UI 状态](https://developer.android.com/develop/ui/compose/state-saving)：旋转等配置变化时保存滚动与界面状态。
